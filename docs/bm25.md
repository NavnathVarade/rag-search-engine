# BM25

## Formula

```
score(q, d) = Σ_{t in q}  IDF(t) * f(t,d) * (k1 + 1)
                          ----------------------------
                          f(t,d) + k1 * (1 - b + b * |d|/avgdl)

IDF(t) = ln( (N - df(t) + 0.5) / (df(t) + 0.5) + 1 )
```

- `f(t,d)`: raw count of term `t` in document `d`
- `|d|`, `avgdl`: document length and corpus-average document length, in tokens
- `N`, `df(t)`: corpus size and number of documents containing `t`
- `k1` (default 1.5): controls term-frequency saturation -- how much a 3rd
  occurrence of a term adds vs a 30th
- `b` (default 0.75): controls length normalization -- 0 disables it
  entirely, 1 fully normalizes by document length

Implementation: `src/rag_engine/retrieval/sparse/bm25.py`.

## Worked example

Corpus (after stopword removal):
```
d1: "cat sat mat"        (3 tokens)
d2: "cat sat on the mat" -> "cat sat mat" after stopword removal (3 tokens)
d3: "dog ran fast"        (3 tokens)
```
`N=3`, `avgdl=3.0`. Query: `"cat"`.

`df(cat) = 2` (d1, d2) → `IDF(cat) = ln((3-2+0.5)/(2+0.5) + 1) = ln(1.64) ≈ 0.494`

For d1: `f(cat,d1)=1`, `|d1|=3` →
`denom = 1 + 1.5*(1 - 0.75 + 0.75*3/3) = 1 + 1.5*1 = 2.5`
`numerator = 1*(1.5+1) = 2.5` → `score = IDF * (2.5/2.5) = IDF(cat) ≈ 0.494`

d3 has zero term overlap with the query, so it scores 0 and is excluded
from results entirely (BM25 only scores documents sharing at least one
query term).

This exact example is asserted in `tests/retrieval/test_bm25.py::test_hand_calculated_bm25_score`.

## Why BM25 can beat dense/semantic search

Query: `"PostgreSQL 16 CREATE INDEX CONCURRENTLY"`

A dense embedding model compresses a chunk into a fixed-size vector
optimized for *topical* similarity. A chunk about "creating indexes in
Postgres" embeds close to the query whether it's about version 12 or 16,
and whether the exact command is `CREATE INDEX` or `CREATE INDEX
CONCURRENTLY` -- the model was never trained to treat those token-level
differences as decisive, because most of the time they aren't.

BM25 rewards *exact token overlap*, weighted by how rare/informative that
token is corpus-wide (IDF). `CONCURRENTLY` and `16` are high-IDF tokens
across a general docs corpus (they appear in relatively few chunks), so a
chunk containing them verbatim scores far higher than one merely "about
indexing" -- see
`tests/retrieval/test_hybrid.py::test_bm25_only_finds_exact_technical_term`
and `test_readiness_vs_liveness_distinguished_by_bm25` for measured
examples of this on a toy corpus.

This is exactly why the hybrid pipeline fuses both signals via RRF
(docs/hybrid-search.md) instead of picking one.
